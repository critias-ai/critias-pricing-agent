# React chat UI options for Pricing Harness

Research snapshot: 2026-10-09. I compared official project documentation and repository/package sources for ten existing React options. This is a practical shortlist for the current app, not a feature-by-feature procurement audit. No packages were installed and the effort estimates are untested frontend estimates.

I used the current official documentation and package/repository sources as a basic maintenance and compatibility screen, but did not audit commit/release cadence or issue response consistently across all ten projects. Before choosing a package, recheck its latest release, exact React peer range, and license; NLUX's React 19 peer range remains specifically unconfirmed here.

## What the app needs

The UI is React 19/Vite with a small custom `Chat.tsx` that currently renders `{id, role, text}` messages. Fastify already owns chat and session state: the browser sends messages and files to the app, restores the `/session` snapshot, and receives app-specific progress events over `EventSource` at `/api/events`. Cancellation and file upload also have existing endpoints. The Outputs sidebar and sandboxed report-preview iframe are separate parts of the product.

The app currently streams workflow progress, then appends the completed answer; it does not stream answer tokens. A library's token-stream support is a capability, not a behavior this app would acquire just by changing its UI. Likewise, the server's existing history remains the persistence authority; a UI library does not automatically persist this app's sessions. None of the choices below requires replacing Fastify or Pi/OpenRouter, but options that include a runtime need an adapter from their message/send model to the app's endpoints and events.

The ranking favors an easy fit with existing state and controls, custom message rendering for future Plotly/OpenUI content, and React 19 compatibility. It also accounts for styling/dependency work and whether the library brings a chat runtime the app does not need.

## Shortlist and recommendation

1. **assistant-ui** is the best fit for the current application. Use `ExternalStoreRuntime` as a view adapter around the existing app state and endpoint calls; leave Fastify's session snapshot and message history as the source of truth. The documented adapter maps the current text shape directly and supports `onNew`, cancellation, running state, attachments, and message conversion. That means this is an incremental UI replacement, not a backend migration. Start with the current text/status interface; custom OpenUI/Plotly blocks can be added when the message/event contract actually exposes structured content.
2. **Ant Design X** is the best alternative if polished built-in styling and attachments matter more than preserving the current CSS conventions. It can be used as components alone or with a custom chat provider, but adopting its design system is a deliberate dependency choice.
3. **Deep Chat** is the fastest isolated-widget experiment. It is less attractive as the long-term app shell because state synchronization and React-based custom output rendering are less direct.

For generated UI specifically, consider **OpenUI as a follow-on renderer**, not an assumed drop-in replacement. The official assistant-ui integration exists, but using OpenUI-generated components requires the backend/runtime to provide tool definitions, tool calls/results, or compatible structured message parts. The current public event/message shape is text and workflow progress, and current chart reports are separate Plotly artifacts. Until that lifecycle is deliberately connected, assistant-ui alone is the smaller step.
