# Windows support plan (2026-10-18)

Goal: the app installs, starts and runs an analysis on Windows. Branch `feat/windows` (from `feat/thin-analyst` at 2aa1510).

Decisions (user, 2026-10-18): Git for Windows' `bash.exe` is required, as the agent SDK already requires it; testing is a `windows-latest` CI job only, with no paid model run.

## Changes

1. `src/agent/workflow/supervised-shell.ts`: take the shell from the SDK's `getShellConfig()` instead of `/bin/bash`; on Windows stop a command with `taskkill /T /F` so Python children die too.
2. `src/agent/workflow/stage-runner.ts`: on Windows kill the worker's whole process tree with `taskkill /T /F`.
3. Paths in analyst prompts use forward slashes on Windows (`toShellPath`), so Git Bash does not eat backslashes and the Python-run nudge still matches. Sites: `stage-prompt.ts`, `session.ts`, `nudges.ts`, `worker.ts`.
4. `scripts/setup-windows.ps1` and `scripts/start-windows.ps1`, mirroring the macOS scripts; venv Python is `.venv\Scripts\python.exe`.
5. Tests: a `venvPython` helper replaces hard-coded `.venv/bin/python`; tests stay as they are otherwise.
6. `.github/workflows/ci.yml`: `windows-latest` job runs typecheck, vitest and pytest.
7. README and `docs/local-setup.md`: Windows quick start.

Out of scope: eval scripts under `scripts/eval-*.mjs` and `tests/evals/run.ts` (dev-only, POSIX).

## Verification

macOS: typecheck, vitest, pytest still pass. Windows: CI green after the branch is pushed (needs the user's go-ahead).
