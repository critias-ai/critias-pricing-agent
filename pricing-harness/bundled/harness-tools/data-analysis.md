# Data guide

- **SQL session:** the `query` tool runs DuckDB over every source file, which is already a typed view named after the file (`sales_transactions`, `product_master`...). Source columns are typed from their profile; text stays text, and a view is not created if casting would lose present values. Views and tables you create persist for the conversation, so define a population or measure once and query or drill into it later.
- **Fewer, larger steps:** most answers need three steps, and a fourth when there is something to show. (1) Reduce: one `query` call that builds the item × period table the answer needs (quantity, sales, cost and any flags) and saves it with `save`. (2) Compute: one Python script over that small table that prints every figure the answer needs: totals, rates, changes, the bridge and the required checks. (3) Revise: when the user corrects something, edit the reduction or the script and run it again rather than rebuilding step by step. (4) Show: when the answer is a series over time, a ranking, a bridge, a breakdown or a distribution, save it and `present` it as a table with a chart; the visualize skill says which chart fits. One `query` call may hold several statements separated by semicolons; each result comes back separately and a failure does not stop the others. `SHOW TABLES` and `DESCRIBE <view>` list what exists. Quote identifiers or avoid reserved words (`rows`, `names`, `types`, `all`, `name`) and always write `AS` before an alias.
- **Scripts:** Python run with `execute_analysis` or with `python3` in `bash` is recorded as evidence. Scripts read files the query tool saved; filtering, grouping and sums of source rows belong in SQL, where they are checked. Write results a user should see to a CSV and `present` it.
- **Size:** compute on the full population in SQL. The query tool shows up to 100 rows; `save` writes the whole result to a CSV.
- **Findings:** `findings.json` in the findings directory lists anomalies. `flags.parquet` beside it maps `finding` to `rid`, the `rowid` in `src_<name>.raw`; `fix` is a SQL rewrite of `column`. Apply a treatment only after the user confirms it.
